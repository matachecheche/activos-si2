================================================================================
 DE CERO A AZURE: GUIA DE PUNTA A PUNTA (Sprint 3)
================================================================================

Este archivo es el camino completo, en orden, para tener el sistema funcionando
en Azure con cobros reales y la app movil apuntando a ese despliegue.

Si solo quieres configurar las pasarelas, abre `LEEME_PASARELAS.txt`.
Si solo quieres los datos de multiempresa y respaldos, `LEEME_MULTIEMPRESA_Y_PAGOS.txt`.


--------------------------------------------------------------------------------
PASO 1. GENERAR EL PROYECTO (Windows)
--------------------------------------------------------------------------------

    python generar_proyecto_sprint3.py

Crea la carpeta `ActivosFijos-Sprint3` con TODO el codigo (web, backend, movil,
base de datos, scripts). Es idempotente: si la carpeta ya existe, hace un
respaldo en `.backup_generador/<fecha y hora>/` y solo cambia lo que cambio.

Si no tienes el generador a mano, el archivo es el unico que necesitas:
copialo a la carpeta donde quieras trabajar y ejecuta el comando de arriba.


--------------------------------------------------------------------------------
PASO 2. PROBAR TODO EN LOCAL (opcional, pero recomendado)
--------------------------------------------------------------------------------

    cd ActivosFijos-Sprint3
    iniciar_proyecto.bat          (doble clic)

Levanta PostgreSQL, aplica el esquema, siembra los datos de fabrica, compila y
arranca la web en http://localhost:4200 y la API en http://localhost:8080.
Para parar: `detener_proyecto.bat`.

Usuarios de prueba: `admin@uagrm.edu.bo` / `admin123` (administra dos empresas).

Si solo quieres la base de datos desde cero: `restaurar_bd_cero.bat`.


--------------------------------------------------------------------------------
PASO 3. CREAR LA BASE DE DATOS EN NEON (gratis, sin tarjeta)
--------------------------------------------------------------------------------

1. Entra en https://console.neon.tech y crea una cuenta con GitHub.
2. Crea un proyecto (plan Free), una rama y una base de datos.
3. Copia la cadena de conexion: se parece a
       postgresql://usuario:clave@ep-xxxx-pooler.us-east-2.aws.neon.tech/neondb?sslmode=require
   (usa el host con "-pooler" para las conexiones desde Azure).
4. Guardala en un archivo `cadena_neon.txt` o copiala cuando la pida el script.

El plan Free de Neon es suficiente para la demo y para la entrega del curso.


--------------------------------------------------------------------------------
PASO 4. DESPLEGAR EN AZURE (App Service F1 + Neon)
--------------------------------------------------------------------------------

    cd ActivosFijos-Sprint3
    python desplegar_azure.py --neon-cadena "postgresql://usuario:clave@ep-xxxx-pooler.us-east-2.aws.neon.tech/neondb?sslmode=require"

El script hace TODO, en este orden:

  1. Crea (o reutiliza) el grupo de recursos, el App Service F1 y el perfil.
  2. Compila la web de Angular con `apiUrl='/api'` y la mete DENTRO del JAR.
     => web y API quedan en el MISMO sitio: https://TU-WEBAPP.azurewebsites.net
  3. Sube el JAR al App Service (Windows/Linux/jar) y lo configura con Java 17+.
  4. Aplica `database/schema.sql` en Neon.
  5. Arranca la app y espera a que la base este lista.
  6. Siembra los datos de fabrica (activos, presupuestos, empresas, permisos...)
     y **comprueba que ninguna tabla de negocio haya quedado vacia**.
  7. Fija las variables de entorno, **incluida `APP_URL_PUBLICA`** (sin ella los
     webhooks apuntarian a localhost y ningun pago se confirmaria).
  8. Verifica el resultado y te imprime la URL.

Perfiles: el Sprint 3 usa `.azure-despliegue-sp3` (aislado del Sprint 1/2), asi
que el segundo despliegue crea OTRA web y otra base, sin pisar la anterior.

Comandos utiles:

    python desplegar_azure.py --solo-app      # recompila, redespliega y re-siembra
    python desplegar_azure.py --logs           # ver el log del backend en Azure
    python desplegar_azure.py --estado          # muestra los recursos y la URL

Si algo quedo a medias, no da por bueno el despliegue: el script reporta el
error real (tablas vacias, seeds fallidos) en vez de decir "DESPLIEGUE TERMINADO".


--------------------------------------------------------------------------------
PASO 5. CONFIGURAR LA PASELA DE PAGO (real, no simulada)
--------------------------------------------------------------------------------

    python configurar_pasarelas.py

El asistente te pide las claves del proveedor que elijas (Mercado Pago, PayPal,
Stripe o QR Simple), **las valida contra la API real** y las guarda cifradas en
el App Service. Al final te imprime la URL del webhook:

    https://TU-WEBAPP.azurewebsites.net/api/pagos/webhook

Registra esa URL en el panel del proveedor (el evento exacto de cada uno esta
en `LEEME_PASARELAS.txt`).

Para revisar como quedo:

    python configurar_pasarelas.py --verificar

PROBARLO EN LOCAL ANTES DE DESPLEGAR (recomendado):

    copy pasarelas.env.ejemplo pasarelas.env     (rellena tus claves de test)
    iniciar_proyecto.bat                         (el backend carga el archivo solo)
    python configurar_pasarelas.py --probar-pago --url-publica http://localhost:8080

El script crea un checkout real en la pasarela y te dice como confirmarlo
(tarjeta de prueba 4242... y el boton "Ya pagué: comprobar estado"). Los
detalles, en `LEEME_PASARELAS.txt` seccion "1 BIS".

Despues: entra a la web, "Suscripcion", elige plan y metodo de pago, y prueba
con la tarjeta de prueba del proveedor (Stripe: 4242 4242 4242 4242).


--------------------------------------------------------------------------------
PASO 6. GENERAR EL APK PARA AZURE (Windows)
--------------------------------------------------------------------------------

    Generar_APK_Azure.bat

El script toma solo la URL de tu despliegue (del perfil `.azure-despliegue-sp3`)
y compila el movil con:

    --dart-define=API_URL=https://TU-WEBAPP.azurewebsites.net

Sale `ActivosFijos-SP3-movil-azure.apk`. Se instala como una app NUEVA
(`com.uagrm.activos.sp3`), convive con la del Sprint 2 y no la reemplaza.

Requisitos: Android SDK + JDK 17. El primer build descarga dependencias
(puede tardar 10-20 minutos segun la conexion).


--------------------------------------------------------------------------------
PASO 7. COMPROBAR QUE TODO ESTA BIEN
--------------------------------------------------------------------------------

En el movil (con la app instalada):

  [ ] Login con admin@uagrm.edu.bo / admin123
  [ ] El menu lateral abre y cierra sin quedar atrapado
  [ ] Se ven activos, presupuestos, mantenimientos, proveedores, inventario,
      respaldos, consultas guardadas, bitacora, IA y suscripcion
  [ ] "MIS EMPRESAS" permite cambiar de empresa y los datos cambian
  [ ] "+ Agregar empresa" abre el formulario y registra una empresa nueva
  [ ] Respaldos: crear, descargar y restaurar
  [ ] Suscripcion: elegir plan y ver el aviso de que falta credencial (o pagar)

En la web (mismo navegador):

  [ ] La web carga con estilos (no sale sin CSS) y el QR de pago se ve
  [ ] "Suscripcion" muestra el estado real de las pasarelas
  [ ] El webhook responde: `python configurar_pasarelas.py --probar-webhook`

En el servidor:

    python configurar_pasarelas.py --verificar   # estado real de las 4 pasarelas
    python desplegar_azure.py --estado            # recursos y URL del despliegue
